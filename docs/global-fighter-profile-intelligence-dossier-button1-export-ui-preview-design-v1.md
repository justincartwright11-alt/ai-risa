# Global Fighter Profile Intelligence Dossier - Button 1 Export UI Preview Design (v1)

## 1. Purpose
Define how the copy-safe dossier export preview is presented inside Button 1 while preserving strict read-only governance.

This slice is docs-only.

## 3. Core Rule
Button 1 may show a copy-safe export preview.
Button 1 may not generate, save, deliver, mutate, or write anything.

## 4. Scope
### In Scope
- Render a read-only preview panel in Button 1 for operator review.
- Show copy-safe summary text generated by preview pipeline.
- Show explicit read-only safety indicators.
- Allow non-mutating operator actions such as select text and copy text.

### Out of Scope
- Real export generation.
- Filesystem output.
- PDF creation.
- Email/share/delivery.
- Profile create/update/merge.
- Database or ranking writes.
- Result/report/learning/calibration mutations.

## 5. UI Surface Design
### 5.1 Placement
- Place preview in Button 1 workflow after dossier context is loaded.
- Preview panel is visible only when sanitized dossier input exists.

### 5.2 Panel Sections
- Header: Export Preview (Read-Only).
- Safety badges: Preview Only, No Writes, No Delivery.
- Body: Monospaced copy-safe summary text block.
- Metadata row: preview_only=true, export_performed=false, file_write_performed=false, delivery_performed=false.
- Footer disclaimer: No profile/database/ranking/report/learning/calibration mutations performed.

### 5.3 Allowed UI Actions
- Copy preview text.
- Collapse or expand preview panel.
- Refresh preview from current in-memory sanitized dossier data.

### 5.4 Forbidden UI Actions
- Download, Save, Export File, Generate PDF, Send, Deliver, Publish.
- Any button that implies persistence or transmission.

## 6. Data Contract for UI Binding
UI binds only to read-only preview contract fields:
- preview: string
- preview_only: true
- export_performed: false
- file_write_performed: false
- delivery_performed: false
- profile_create_update_merge: false
- database_ranking_writes: false
- result_report_learning_calibration: false

UI must not bind or render:
- internal_notes
- write flags
- merge instructions
- private operator fields
- raw internal source payloads

## 7. Safety and Sanitization Rules
- Treat preview string as plain text, not HTML.
- Escape or exclude HTML/XSS payloads before rendering.
- Do not inject preview content into raw HTML containers.
- If sanitization status is uncertain, fail closed and show blocked state.

## 8. Fail-Closed Behavior
- Missing dossier fields: render safe defaults and keep all flags false.
- Invalid preview payload: show non-actionable warning and disable copy action.
- Any detected write-intent field in payload: suppress panel and raise internal diagnostic only.

## 9. Telemetry Constraints
Allowed telemetry:
- Preview rendered event.
- Copy action event.
- Safety-block event.

Forbidden telemetry payloads:
- Raw dossier internals.
- Sensitive free-text notes.
- Any write instruction data.

## 10. Acceptance Criteria
- Copy-safe summary is visible and readable in Button 1 UI preview panel.
- preview_only=true is shown.
- export_performed=false is shown.
- file_write_performed=false is shown.
- delivery_performed=false is shown.
- profile_create_update_merge=false is shown.
- database_ranking_writes=false is shown.
- result_report_learning_calibration=false is shown.
- No file generation controls appear.
- No delivery controls appear.
- No mutation path is reachable from preview UI.

## 11. Non-Goals
- Implementing any export backend.
- Enabling PDF/report generation from this UI.
- Introducing new persistence or transport APIs.

## 12. Release Gate
This design may proceed to implementation only as a UI preview surface that consumes existing read-only preview output.
Any future export, PDF, delivery, or write behavior requires a separate design slice and explicit operator gate review.

## 13. Final Verdict
The Button 1 export UI preview is locked as read-only display-only behavior, preserving the three-button governance model and zero-write guarantees.
